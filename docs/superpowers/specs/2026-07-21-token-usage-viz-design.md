# Token usage visualizations for README

## Problem

The README's `## Costs` section makes two claims with no supporting
data: that Claude opponents are "roughly 10x cheaper" after the first
(cache-warm) decision, and implicitly that model choice
(`## Choosing a model`) affects cost. Neither claim is backed by a
picture. Two small charts, generated from real match data, fix that.

## Data sources (already exist, no new instrumentation)

- **Per-decision detail**: `--debug` JSONL transcript
  (`internal/debuglog/debuglog.go`), one `agent_call` event per
  decision with fields `seq`, `tokens_in`, `tokens_out`, `cache_read`,
  `cache_write`, `cost_usd`.
- **Career totals**: `~/.showdown/stats.json`
  (`internal/stats/stats.go`), keyed by opponent (`haiku`, `sonnet`,
  ...), each a `Record{Wins, Losses, TokensIn, TokensOut, CostUSD}`.

## Data collection

Play two real matches before generating charts:

```
showdown --debug --model haiku
showdown --debug --model sonnet
```

A few hands each is enough. This leaves one debug JSONL per match in
`~/.showdown/` and accumulates both opponents into `stats.json`. The
sonnet match's JSONL is the one used for the per-hand chart (it's the
recommended default, matches the README's own emphasis).

## Script: `scripts/plot_token_usage.py`

New file, stdlib + `matplotlib` (new dependency — first Python script
in this repo to need one; `spike/*.py` are stdlib-only). Docstring
notes `pip install matplotlib`.

```
python3 scripts/plot_token_usage.py \
  --debug ~/.showdown/debug-<timestamp>.jsonl \
  --stats ~/.showdown/stats.json \
  --out docs/
```

Two independent functions, each producing one PNG:

1. `plot_per_hand(jsonl_path, out_path)`
   - Reads `agent_call` events in `seq` order from the JSONL.
   - Stacked bar per decision: `cache_read` tokens (cheap) vs.
     non-cached input tokens (`tokens_in - cache_read`, full price)
     plus `tokens_out`.
   - X axis: decision number. Y axis: tokens.
   - Makes the cache warm-up visible directly: decision 1 has
     `cache_read == 0`, later decisions are mostly cache-read.
   - Output: `docs/token-usage-per-hand.png`.

2. `plot_cross_model(stats_path, out_path)`
   - Reads `stats.json`, filters to keys `haiku` and `sonnet` (the
     two the README's "Choosing a model" section discusses; other
     adapter keys present in the file, if any, are ignored).
   - Grouped bar chart, two groups (haiku, sonnet). Left y-axis: total
     tokens (`tokens_in` + `tokens_out`, stacked or side-by-side bars
     per group). Right y-axis (twin): `cost_usd`, one bar per group.
     These are cumulative career totals, not per-match — axis label
     says "career total" explicitly so it isn't misread as a per-match
     figure.
   - Output: `docs/token-usage-by-model.png`.

Both charts use `plt.style.use('dark_background')` to match the tone
of `docs/demo.gif`. Standard matplotlib chrome otherwise (axis labels,
legend, title) — no ASCII/terminal-font styling.

## Out of scope

- codex/gemini in the cross-model chart (Claude-only, matches existing
  "Choosing a model (Claude)" section scope).
- Automating chart regeneration (e.g. CI, git hook). This is a
  manually-run script; charts are committed as static PNGs and
  regenerated by hand when the data materially changes.
- ASCII/terminal-styled charts (rejected in favor of standard
  matplotlib dark theme — less design effort, same "matches the repo's
  dark aesthetic" goal via `dark_background` style alone).
